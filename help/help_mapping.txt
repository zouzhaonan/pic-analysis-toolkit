Usage:
  pic mapping --out-dir <dir> --sample-sheet <tsv> [options]

Overview:
  Run the full primary RNA workflow:
  demux -> filter primer-derived reads -> map -> count-umi -> summarize-map
  -> generate-bigwig

  Reads whose cDNA part is the RT primer itself (<barcode> followed by a poly-T
  stretch, i.e. primer dimers) are always removed before mapping. They otherwise
  pile up as a handful of barcode-specific phantom genes. Typically ~1% of reads;
  assigned counts, UMIs and detected genes are unaffected.

Required options:
  --out-dir <dir>            Output directory
  --sample-sheet <tsv>       Sample sheet TSV
                             Example:
                             - - - - - - - - - - - - - - - - - - - - - - - - -
                               fastq_prefix  genome  barcode  sample   group
                               brain         mm10    AGGATC   brain_1  brain
                               brain         mm10    TCGAAG   brain_2  brain
                               ovary         mm10    TCCTTC   ovary_1  ovary
                               ovary         mm10    TGTCTG   ovary_2  ovary
                             - - - - - - - - - - - - - - - - - - - - - - - - -
  --raw-fastq-dir <dir>      Directory containing raw paired FASTQ files (R1 & R2)
                             * No need when --demux-fastq-dir is specified

Optional options:
  --threads <n>              Threads per mapping job; also used for demux and
                             UMI counting (default: 8)
  --jobs <n>                 Number of samples mapped at the same time (default: 1)
                             Each job uses --threads, so the total is
                             jobs x threads (e.g. --jobs 4 --threads 8 = 32).
                             A single job hardly gets faster above 8 threads;
                             on a machine with more cores, raise --jobs rather
                             than --threads. Each job loads its own hisat2
                             index, so memory also grows with --jobs.
  --run-name <name>          Run name suffix for output files (default: random 8 chars)
  --demux-fastq-dir <dir>    Directory containing already-demultiplexed FASTQ files
  --simulation               Run in simulation mode (default: off)
  --hisat2-very-sensitive    Add --very-sensitive to hisat2 (default: off)
                             (= --bowtie2-dp 2 -k 50 --score-min L,0,-1)
  --barcode-first            read1 layout is barcode(6) + UMI(6).
                             Default assumes the PIC standard UMI(6) + barcode(6).
                             Use only for libraries built with the two segments
                             swapped; with the wrong setting demux matches almost
                             nothing and samples come out near-empty.
  --hisat2-score-min <spec>  hisat2 --score-min (default: L,0,-1)
                             pic defaults to L,0,-1 because PIC Read2 starts with
                             the RT primer's random hexamer (non-templated by
                             design); hisat2's own default L,0,-0.2 cannot afford
                             to soft-clip it. Measured: unmapped 38-45% -> 1.3-1.7%,
                             UMI 2.4-2.8x. Pass L,0,-0.2 to restore hisat2's default.
                             Preferred over --hisat2-very-sensitive: same yield at
                             ~1/4 the runtime and half the multi-mapping reads.

Examples:
  pic mapping \
    --sample-sheet /path/sample.tsv \
    --raw-fastq-dir /path/raw_fastq \
    --out-dir /path/mapping \
    --run-name test
