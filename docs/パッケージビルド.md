# PIC パッケージ作成手順

**開発者向け**の手順です。`pic` を使うだけなら不要です。
`$repo` はこのリポジトリを clone した場所、`$build_dir` は conda-build の作業場所 (任意) に読み替えること。

以下では `<version>` を今回リリースするバージョン (例 `1.3.0`) に読み替えること。

## 1. 事前準備

- macOS もしくは Linux
- Conda
- conda-build
- GitHub Release を作る場合は `gh` CLI (`gh auth login` 済み)

```bash
conda install -n base -c conda-forge conda-build
```

## 2. バージョンを更新する

`VERSION` と recipe の両方を同じ値にする。`VERSION` は `pic help` の表示に、
recipe はパッケージ名に使われるため、片方だけだと食い違う。

```bash
repo="$HOME/pic-analysis-toolkit"   # clone した場所

echo "<version>" > "$repo/VERSION"
# src/recipe/meta.yaml の {% set version = "..." %} も同じ値に変更する
```

## 3. 生成物を削除する

ビルド用の croot だけを消す。

```bash
build_dir="$HOME/local/conda-bld-pic"

rm -rf "$build_dir"
```

> **`pic` 環境は消さないこと。**
> 動作確認は手順 6 で別名の環境を作って行う。稼働中の解析環境を壊す必要はない。
>
> **`src/pic-channel` も消さないこと。**
> チャンネルは累積で運用しており、過去バージョンの `.conda` を残したまま
> 新しいものを追加する (手順 5)。消すと過去バージョンでの再現ができなくなる。

## 4. パッケージをビルドする

```bash
recipe_dir="$repo/src/recipe"

conda config --set solver libmamba
conda config --set channel_priority strict
conda clean -i -y

conda build "$recipe_dir" \
  --croot "$build_dir" \
  --override-channels \
  -c conda-forge -c bioconda
```

`TEST END: .../pic-<version>-0.conda` まで出れば成功。所要時間は数分程度。

## 5. `pic-channel` に追加する

既存の `.conda` は残したまま、新しいものをコピーして再インデックスする。

pic 1.5 から、`pic demux` の振り分けのプログラム `pic-demux` (Rust、`src/pic-demux`) を
build して環境の bin に入れるので、パッケージは `noarch` ではなく OS ごと
(Mac は `osx-arm64`、Linux は `linux-64`) になる。使う OS ごとにその OS で手順 4 を行い、
それぞれの `<subdir>` に置く (1.4.0 までの `noarch` のものは残す)。
build のときに crates.io から Rust の部品を取ってくるので、ネットにつながっていること。

```bash
channel_dir="$repo/src/pic-channel"
subdir=linux-64   # Mac では osx-arm64

mkdir -p "$channel_dir/$subdir"
cp "$build_dir/$subdir/pic-<version>-"*.conda "$channel_dir/$subdir/"
conda index "$channel_dir"

cd "$repo/src"
rm -f pic-channel.zip
zip -r pic-channel.zip pic-channel
```

`repodata.json` に全バージョンが、`current_repodata.json` に最新のみが
載っていることを確認する。

```bash
python3 -c "
import json
d = json.load(open('$channel_dir/$subdir/repodata.json'))
print('repodata:', sorted(v['version'] for v in d['packages.conda'].values()))
c = json.load(open('$channel_dir/$subdir/current_repodata.json'))
print('current :', sorted(v['version'] for v in c['packages.conda'].values()))"
```

## 6. インストールを確認する

**別名の環境**を作ってチャンネルから入るかを確かめる。稼働中の `pic` 環境には触れない。

```bash
conda create -y -n pic-test -c "$channel_dir" -c conda-forge -c bioconda \
  --override-channels pic=<version>

conda run -n pic-test pic help | head -1   # pic <version> と出れば OK
conda run -n pic-test pic-demux --version  # pic-demux が入っていること
```

確認が済んだら片付ける。

```bash
conda env remove -n pic-test -y
```

## 7. コミットする

```bash
cd "$repo"
git add -A VERSION src/
git commit -m "release: pic <version> パッケージを pic-channel に追加"
git push origin master
```

## 8. タグと Release を作る

タグはマージコミットに対して打つ。

```bash
git tag -a v<version> -m "PIC v<version>

<変更点の要約>"
git push origin v<version>

gh release create v<version> src/pic-channel.zip \
  --title "pic <version>" \
  --notes-file <リリースノート.md>
```

GitHub の Web UI から作る場合は Releases → Draft a new release で、
Tag に `v<version>`、Title に `pic <version>` を入れ、`pic-channel.zip` を
添付して Publish する。

## 付録: パッケージを使わず git の checkout で pic を動かすとき

`bin/pic` を直接呼ぶ使い方 (workstation の `~/pic_seq/pic-analysis-toolkit` など) では、
`pic demux` が呼ぶ `pic-demux` を自分で build する。環境 pic に `rust` を足し
(C コンパイラは環境 pic にすでにある。無ければ `c-compiler` も)、`src/pic-demux/install.sh` を回すと、
その checkout の `bin/pic-demux` (git に入れない) に置かれる。`bin/pic` は自分の隣の `bin/pic-demux` を
最初に使い、無いときだけ PATH の `pic-demux` を使う。checkout や写し (git worktree) ごとに回せば、
版ごとに `pic-demux` を持てる (pic_lanes は写しを作るたびに回す)。

build したものは `src/pic-demux` の中身の hash ごとに `${XDG_CACHE_HOME:-~/.cache}/pic-demux/<hash>/`
(`PIC_DEMUX_CACHE` で変えられる) に取っておくので、中身が同じなら build せずに写すだけで終わる。

```bash
conda activate pic                       # workstation では source ~/pic_seq/env.sh
conda install -n pic -c conda-forge rust # 1 回だけ
bash "$repo/src/pic-demux/install.sh"    # git pull のあとに回す (変わっていなければすぐ終わる)
"$repo/bin/pic-demux" --version
```
