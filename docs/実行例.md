# pic 解析パイプライン実行例

ヒト（hg38）のテストデータで、`pic` の基本ワークフローを確認します。
テストデータは PIC-seq の実データ（4 サンプル・2 群。`R6_CTRL` と `Lig_CTRL` が各 *n* = 2）から、約 43 万リードペアを無作為に抜き出したものです（約 22 MB）。
`pic all` 1 本で mapping → DESeq2 → ORA/GSEA → HTML レポートまで実行し、最後にレポートをブラウザで開きます。

## 1. データセットを準備

```bash
mkdir -p "$HOME/tmp"
cd "$HOME/tmp"
curl -L "https://github.com/zouzhaonan/pic-analysis-toolkit/releases/latest/download/pic_test.tar.gz" | tar zx

wd="$HOME/tmp/pic_test"
```

hg38 のリファレンスが入っている必要があります（[導入方法](導入方法.md)）。

## 2. conda 環境を有効化

```bash
shell_name="$(basename "${SHELL:-zsh}")"
eval "$("$(command -v conda)" "shell.${shell_name}" hook)"
conda activate pic
```

`conda activate pic` を忘れると、`pic` コマンドが見つからないか、Linux では別のプログラム（groff の `pic`）が動きます。

## 3. `pic all` で一括実行

```bash
pic all \
  --sample-sheet "$wd/sample_sheet__test.txt" \
  --raw-fastq-dir "$wd/fastq" \
  --out-dir "$wd" \
  --run-name test
```

最後に `pic all: 完了しました` と表示されれば終了です。Apple Silicon Mac で 3 分ほどかかります（mapping のあと enrichment とレポート作成が続きます）。

`mapping_sum` に 4 サンプルが並び、それぞれ `total` が 8〜15 万リードほどあることを確認します。

```bash
cat "$wd/summary/mapping_sum__test.tsv"
```

## 4. レポートを開く

```bash
open "$wd/report_test_hg38.html"
```

レポートは 1 つの HTML にすべてのデータを埋め込んであるので、このファイルだけを人に渡しても見られます（このデータで約 6 MB）。
`R6_CTRL` vs `Lig_CTRL` の比較で DEG が出ます。
主な出力は次のとおりです（`<run>_<genome>` = `test_hg38`）。

| 場所 | 中身 |
| --- | --- |
| `$wd/summary/` | `mapping_sum__test.tsv`、`deftable_test_hg38.tsv` など |
| `$wd/deseq2/` | `stats_test_hg38.csv`、`normalizedCountTable_test_hg38.csv`、`DEG_test_hg38/` など |
| `$wd/enrich/` | `GSEA/<method>/*.csv`、`ORA/<method>/*.csv` |
| `$wd/report_test_hg38.html` | HTML レポート |

## 5. 応用: サブコマンドを個別に実行

FDR や enrichment の method を変えたいとき、ChIP-Atlas 解析や遺伝子ごとの図が欲しいときは、`pic all` の結果を使ってサブコマンドを個別に実行します。

### 5-1. DESeq2（FDR を変える例）

```bash
pic deseq2 \
  --deftable "$wd/summary/deftable_test_hg38.tsv" \
  --count-dir "$wd/counts" \
  --genome hg38 \
  --fdr 0.05 \
  --out-dir "$wd/custom/deseq2"
```

### 5-2. ORA/GSEA（method を選ぶ例）

```bash
pic enrich \
  --stats "$wd/custom/deseq2/stats_test_hg38.csv" \
  --genome hg38 \
  --methods GO_BP,KEGG \
  --out-dir "$wd/custom/enrich" \
  --deg-clusters "$wd/custom/deseq2/DEG_test_hg38/DEGCluster_test_hg38/DEGCluster_gene_for_ora_test_hg38.csv"
```

`$wd/custom/enrich/` 配下に `GSEA/<method>/*.csv` と `ORA/<method>/*.csv` が作成されれば正常です。

### 5-3. ChIP-Atlas 解析

```bash
pic chipatlas \
  --deftable "$wd/summary/deftable_test_hg38.tsv" \
  --umi "$wd/deseq2/UMI_count_test_hg38.csv" \
  --stats "$wd/deseq2/stats_test_hg38.csv" \
  --genome hg38 \
  --out-dir "$wd/chipatlas"
```

計算は DDBJ の WABI (ChIP-Atlas) で実行されます。完了すると、WABI が返した結果 (tsv と html、ほかに log) が `<out-dir>/<比較>/<比較>__<ea|page>__<種類>.tsv` などにそのまま保存されます（pic で表や図には加工しません）。ジョブ ID・日時・引数は `<out-dir>/run/` に残ります。`--comparisons` で比較を選べ、`--detach` で裏で走らせられます。同じ `--out-dir` で再び実行すると続きから再開します。

EA は比較 A vs B の DEG を「A で高い」「B で高い」に分けて互いを背景にします（全遺伝子を背景にすると組織そのものの性質が前に出るため。互いを背景にすると、処理で乗り方が変わった feature だけが残り、両方に同じだけ乗る feature は目立たない）。DEG の数で足切りはせず、片方が 0 個のときだけ EA を飛ばします。PAGE は生カウント表を渡して全比較で回します。既定の実験の種類は TFs and others / Histone / ATAC-Seq、同時本数は制限なしです。

### 5-4. plot-expression

対象遺伝子ごとに、各群の normalized count をプロットします。

```bash
cat > "$wd/genes.txt" <<'EOF'
PKM
PEG10
APOH
KRT18
EOF

pic plot-expression \
  --count "$wd/deseq2/normalizedCountTable_test_hg38.csv" \
  --deftable "$wd/summary/deftable_test_hg38.tsv" \
  --gene-list "$wd/genes.txt" \
  --out "$wd/plot_expression_test.pdf"
```

`Warning` が出ることがありますが、`$wd/plot_expression_test.pdf` が正常にできていれば問題ありません。

## 6. 後片付け

### 6-1. conda 環境を終了

```bash
conda deactivate
```

### 6-2. テストデータと解析結果を削除（必要な場合のみ）

```bash
rm -rf "$wd"
```
